Tài liệu Autoxide v0.20.0

Tool MCP

Sinh từ docs/mcp-tools.json. Mô tả bằng tiếng Anh.

  • address.list_communes (read-only): List the communes, wards and special zones of a province, in code order. Follow pagination.next_cursor for more.
  • address.list_provinces (read-only): List the provinces of a country (Vietnam), in the order of the official list. Follow pagination.next_cursor for more.
  • address.search_units (read-only): Search administrative units by name, with or without accents (ha noi also finds the accented name).
  • address.validate_address (read-only): Check an address (the commune must belong to the province) and fill in the names of its units.
  • ai.status (read-only): Tell whether the server’s AI features are on (text generation, image reading, embeddings), which provider and models they use, and today’s token use against the daily limit.
  • analytics.funnel (read-only): Sessions reaching each step of a declared funnel on a website over a range of days; steps are counted on their own.
  • analytics.overview (read-only): Visitors, page views, bounce rate, top sources and daily counts of a website over a range of days (from the daily totals).
  • analytics.top_objects (read-only): The most viewed objects (<kind>:<id>, e.g. products) of a website over a range of days, most first; kind keeps one kind; follow pagination.next_cursor.
  • analytics.top_pages (read-only): The most viewed pages of a website over a range of days, most first; the same pages as GET /api/v1/analytics/pages; follow pagination.next_cursor.
  • audit.get_entry (read-only): Get one audit log entry.
  • audit.list_entries (read-only): List audit log entries — who changed what, when, before and after — newest first; filter by user, record, action or module. Follow pagination.next_cursor for more.
  • auth.count_memberships (read-only): Count the people of every organization unit: direct (memberships on the unit) and total (on the unit or a unit above it).
  • auth.count_role_members (read-only): Count the people holding each role (at any unit, each person once).
  • auth.create_api_key (changes data): Create an API key that acts as you, limited to the listed permissions. Needs your current password and a password session: an API key cannot create keys. The result carries the key, shown only once.
  • auth.create_invitation (changes data): Invite someone by email to work at an organization unit with given roles; the mail goes out shortly and the link can be used once.
  • auth.create_oidc_provider (changes data): Add a sign-in provider to this tenant; register the application at the provider first. The client secret is stored encrypted and never shown again.
  • auth.create_role (changes data): Create a role that grants the listed permissions (see list_permissions).
  • auth.delete_oidc_provider (destructive): Remove a sign-in provider from this tenant, with every account link to it.
  • auth.delete_role (destructive): Delete a role; users who had it lose its permissions. You can only delete a role you could take away: you have its permissions as widely, and every permission it bans (auth.role_beyond_you). The built-in admin role cannot be deleted.
  • auth.get_role (read-only): Get one role.
  • auth.get_user_roles (read-only): List the roles of a user (id is the user’s id), by name; follow pagination.next_cursor for more.
  • auth.list_api_keys (read-only): List your API keys (never their secrets); called with an API key, only that key; with an OAuth token, none. Follow pagination.next_cursor for more.
  • auth.list_invitations (read-only): List the invitations at units in your scope, newest first; filter by status.
  • auth.list_memberships (read-only): List who works in which organization unit with which role; filter by unit, role or user, and with inherited also count memberships on the units above.
  • auth.list_my_identities (read-only): List the outside sign-ins (Google, Microsoft, GitHub…) linked to your own account.
  • auth.list_oidc_providers (read-only): List the sign-in providers (Google, Microsoft, GitHub, OpenID Connect) of this tenant, with disabled ones; client secrets are never shown.
  • auth.list_permissions (read-only): List every permission that roles can grant, with what each allows, by name; follow pagination.next_cursor for more.
  • auth.list_roles (read-only): List roles with the permissions they grant; follow pagination.next_cursor for more.
  • auth.list_users (read-only): List user accounts, newest first; search finds users by email or name. Follow pagination.next_cursor for more.
  • auth.replace_role (changes data): Replace the name, description and permissions of a role. You cannot add, widen or unban a permission you do not have as widely (auth.permission_beyond_you), nor turn off requires_mfa of a role you could not give (auth.role_beyond_you). The built-in admin role only changes requires_mfa.
  • auth.revoke_api_key (destructive): Revoke one of your API keys; it stops working at once. Called with an API key, only that same key can be revoked; an OAuth token revokes none.
  • auth.revoke_invitation (changes data): Revoke an invitation: its link stops working.
  • auth.rotate_api_key (changes data): Replace one of your API keys with a new one that has the same name, permissions, unit, allowed addresses and kind. The old key keeps working for overlap_hours (24 by default) so programs can switch. Needs your current password and a password session. The result carries the new key, shown only once.
  • auth.set_memberships (changes data): Replace every organization unit a user works in and the roles there. You can only give or take away roles whose permissions you have, in units you work in, and only take away a role whose banned permissions you all have (auth.role_beyond_you).
  • auth.set_user_roles (changes data): Replace every role of a user with role_ids. You can only give or take away roles whose permissions you have yourself, as widely, and only take away a role whose banned permissions you all have (auth.role_beyond_you). The last administrator cannot lose the admin role.
  • auth.update_oidc_provider (changes data): Change a sign-in provider of this tenant (name, issuer, client, redirect pages, allowed email domains, sign-up, default role, enabled).
  • auth.update_user (changes data): Rename, disable or enable a user account. Disabling signs the user out everywhere; the last active administrator cannot be disabled.
  • auth.whoami (read-only): Get the calling user (id, email, name) and the permissions they hold. Start here to learn what you may do.
  • automations.create_rule (changes data): Create a “when … then …” automation rule. trigger: {"type": "event", "event": "<module>.<event>"}, {"type": "schedule", "every": "day", "hour": 9}, {"type": "manual"} or {"type": "metric", …}; conditions: a tree of all / any / not over {"field": "event.total", "op": "gt", "value": 5000000}; actions: [{"tool": "<module>.<tool>", "arguments": {…}}], values may use {{ event.… }}; see GET /api/v1/automations/catalog for the triggers and tools. Rules you create as an agent wait until a person enables them; try a rule with automations.test_rule.
  • automations.get_rule (read-only): Get an automation rule in your scope: trigger, conditions, actions and status.
  • automations.list_rules (read-only): List the automation rules in your scope, newest first; follow pagination.next_cursor for more.
  • automations.test_rule (read-only): Dry-run an automation rule on a sample: whether the conditions hold, the arguments after filling the templates, and what would fail (unknown tool, missing permission of the person the rule runs as, wrong arguments). Calls no tool.
  • automations.update_rule (changes data): Change an automation rule in your scope. Changing the trigger, conditions or actions checks the whole rule again with your permissions; changed by an agent, the rule waits until a person enables it again.
  • bookings.availability (read-only): Find free start times of a service between from and to (at most 31 days), with the price, deposit and cancellation terms to tell the customer before booking.
  • bookings.cancel_booking (destructive): Cancel a booking for the shop: the place is freed and any deposit paid is refunded in full through the payment partner.
  • bookings.create_booking (changes data): Book a free time for a customer (phone call, walk-in). Confirmed at once, no deposit. Fails with bookings.slot_taken if the time was just taken.
  • bookings.list_bookings (read-only): List the bookings of your units, newest first; filter by status, staff member and start time.
  • bookings.reschedule_booking (changes data): Move a booking to another free time (and optionally another staff member). If the new time was just taken, the booking keeps its old time.
  • catalog.add_prices (changes data): Add up to 500 prices to a price list. Rows are only added, never changed; a future valid_from schedules a price and valid_to makes it temporary.
  • catalog.create_product (changes data): Create a product as a draft with its first variant (SKU unique in the tenant).
  • catalog.delete_product (destructive): Delete a product that was never on sale, with all its variants. It cannot be restored; archive products that were on sale instead.
  • catalog.get_product (read-only): Get a product with its texts, options, variants, categories and images.
  • catalog.import_status (changes data): Status of an import you started, with the counts and the errors by row.
  • catalog.list_categories (read-only): List the categories of the tenant, by depth then display order (parents before children); follow pagination.next_cursor for more.
  • catalog.list_collections (read-only): List the product collections in your scope (manual or by rule), newest first, each with its version.
  • catalog.list_products (read-only): List the products in your scope, newest first; filter by status, kind, unit, category, readiness or words; follow pagination.next_cursor for more.
  • catalog.resolve_price (read-only): Resolve the price of a variant at a store (optionally for a customer group, at a time) and show which price lists applied, in selection order.
  • catalog.save_collection (changes data): Draft a product collection, or change one (with id and version): texts and SEO by language, a rule (categories, attributes, price range, new, on promotion) or chosen products in order, and the sort. A tool never turns a collection on: a person sets it active.
  • catalog.set_product_status (changes data): Put a product on sale (active), stop it (inactive), archive it, or reopen an archived product as a draft. On a marketplace, goods of a seller go on sale only once the seller has verified its identity (compliance.kyc_required, catalog.seller_verification_unavailable).
  • catalog.start_import (changes data): Import products from a CSV file in the background: a known SKU updates that variant and its text, a new SKU creates a draft product. Nothing is put on sale. Follow with import_status.
  • catalog.suggest_copy (changes data): Ask AI for a draft short description, description and SEO texts of a product. The draft changes nothing until a person applies it (POST /api/v1/catalog/suggestions/{id}/apply).
  • catalog.update_product (changes data): Change the tax category, warranty, tracking or default language of a product.
  • catalog.upsert_variant (changes data): Create a variant (give product_id and create) or change one (give id and update).
  • comments.answer (changes data): Answer a shown question (a top-level comment) as yourself, like a signed-in user on the website: the answer carries your badges on the target (e.g. seller), follows the same moderation and may wait for approval. Needs a display name (PUT /api/v1/comments/profile) and, on some kinds, a verified account.
  • comments.get (read-only): Get a comment in any status with its moderation details and its version, needed to approve, reject or mark it as spam.
  • comments.moderate (changes data): Approve (published), reject (rejected), mark as spam (spam) or hold again (pending) a comment. Approving shows it and mails people following the comment it answers. Pass the version you read.
  • comments.queue (read-only): List comments for moderation, newest first: by default those waiting for approval (pending), with their text, author, email, hold reason and report count. Follow pagination.next_cursor with the same filters for more.
  • comments.set_target_state (changes data): Open or close the comments of a target (open / closed); closed targets take no new comments, existing ones stay shown.
  • comments.unanswered (read-only): List shown questions (top-level comments, e.g. on a product) that have no shown answer yet, newest first, with their text, author and badges. Answer one with comments.answer. Follow pagination.next_cursor with the same filters for more.
  • compliance.account_verification (read-only): Your account verification level for posting content (Vietnam, Decree 147/2024): none, phone (mobile number confirmed by SMS code) or identity (identity verified), with the verified number masked. Codes are sent and confirmed only through REST (POST /api/v1/compliance/me/phone-verifications).
  • compliance.add_case_note (changes data): Add an internal note to the log of a case (what was checked, who was contacted).
  • compliance.add_incident_entry (changes data): Add a line (what was found, what was done) to the log of a personal data breach.
  • compliance.documents (read-only): List the legal documents of the tenant (terms of use, privacy policy…) with their current version number, by kind; follow pagination.next_cursor for more.
  • compliance.get_case (read-only): Get a report or complaint with its log (notes, answers of the reported party, restrictions, decision).
  • compliance.incident_draft (changes data): A draft notification of a personal data breach to the authority (authority) or to the people affected (subjects). A draft only: a person completes, reviews and sends it.
  • compliance.incidents (changes data): List personal data breaches with their 72-hour reporting deadline (overdue for those late).
  • compliance.kyc_profiles (read-only): List the identity verification profiles of the tenant (results only, never document images or full numbers).
  • compliance.legal_profiles (read-only): List the legal (owner) profiles of the tenant and its units: what Vietnamese law requires a commerce website to show about its owner.
  • compliance.list_cases (read-only): List reports of infringements (intellectual property, counterfeit, prohibited goods) and consumer complaints, with their deadlines (overdue for those late).
  • compliance.open_incident (changes data): Record a personal data breach. The report to the authority is due 72 hours after detection; reminders go to the incident.alert_emails policy.
  • compliance.pending_acceptances (read-only): The legal documents you must accept (again) before going on, by kind; follow pagination.next_cursor for more.
  • compliance.processing_register (read-only): The register of processing activities: purposes, legal bases, kinds of data, recipients, retention and where the data is kept.
  • compliance.publish_document_version (changes data): Publish a new version (or a translation) of a legal document. A published version never changes. Draft texts with AI only as suggestions for a person to review.
  • compliance.purposes (read-only): List the tenant’s purposes for processing personal data with their legal basis (Vietnam, Personal Data Protection Law 91/2025/QH15), by key; follow pagination.next_cursor for more.
  • compliance.record_subject_request (changes data): Record a request of a data subject received through another channel; the due date comes from the legal rule privacy.subject_requests. Fulfilling it (export / erase) is done through REST by a person.
  • compliance.restrict_case_target (changes data): Hide the target of an open case while it is handled (the owning module hides it, e.g. a page answers 451). Deciding the case needs a person through REST.
  • compliance.retention (read-only): How long each kind of personal data is kept, compared with the limits of the legal rule privacy.retention_limits (ok, exceeds_limit, forever_not_allowed), by module and name; follow pagination.next_cursor for more.
  • compliance.set_website_status (changes data): Record what happened with a website’s file at the Ministry of Industry and Trade (submitted, notified, registered…). notified / registered need the logo code the ministry gave.
  • compliance.subject_requests (read-only): List the requests of data subjects received by email, post, phone or from an authority, with their due date (overdue for those late).
  • compliance.tracking_tags (changes data): List the advertising and analytics tracking tags of the websites in your scope (GA4, GTM, Google Ads, Meta, TikTok, Zalo); they load only after visitor consent.
  • compliance.unlock_phone (changes data): Unlock sign-in codes for a phone number locked after too many wrong codes in a row, so its owner can sign in with a code again; a number that is not locked is left as it is. Write numbers outside Vietnam as + and the country code. Check who asks first; the audit log records who unlocked it.
  • compliance.verification_status (read-only): Your identity verification (KYC) status: none, pending, in_review, info_requested, verified, rejected, expired or revoked.
  • compliance.website_checklist (read-only): What a website still lacks before it is notified to / registered with the Ministry of Industry and Trade; each item is met, missing, unknown or manual, with what to do.
  • compliance.website_dossier (read-only): The draft dossier of a website for the Ministry of Industry and Trade, filled from the tenant’s data (declaration; for a marketplace a draft project plan and regulations). A person reviews it with a legal professional and submits it on online.gov.vn.
  • compliance.websites (read-only): List the websites of the tenant with their kind (sales → notify the Ministry of Industry and Trade, platform → register) and status.
  • content.compose_page (changes data): Ask the AI to build a page’s block layout from a description. Runs in the background and ends as a draft marked ai_assisted, never published; follow it with get_page_layout or REST GET /entries/{id}/ai/thread. Counts toward the plan’s monthly AI page builds.
  • content.create_campaign_drafts (changes data): Draft a campaign from a promotion: a landing page (page), a text banner (banner, needs banner_placement) and a newsletter campaign (newsletter, needs newsletter_list_id). Everything is a draft in its own module — nothing is published or sent; a person reviews each one. Runs in the background: read the outcome with get_campaign_drafts. Counts once toward the plan’s monthly AI page builds.
  • content.create_draft (changes data): Create a post or page as a draft (not visible to readers until published). The slug is made from the title unless given.
  • content.draft_from_template (changes data): Make a draft page from a mandatory page template, filled with the unit’s legal profile and the given variables. It stays a draft until a person reviews and publishes it.
  • content.edit_page (changes data): Ask the AI to change a page’s block layout in words (“make the hero red”); selection limits it to some blocks. Runs in the background; the result is a new draft and the turn keeps the revision before it to undo.
  • content.get (read-only): Get a post or page: its draft (title, slug, summary, body, images, SEO fields, status) and its version, needed to change it.
  • content.get_campaign_drafts (read-only): Get a campaign draft request: its status and, once finished, the draft made for each channel (kind and id) or why that channel failed (error_code).
  • content.get_page_layout (read-only): Get the draft body of a page (its block layout) with the version to pass to update_page_layout.
  • content.get_translation_request (read-only): Get an AI translation request: status (queued, running, succeeded, failed), the translation’s draft (result_entry_id) or why it failed (error_code).
  • content.legal_templates (read-only): List the mandatory page templates for a commerce website in Vietnam (owner information, privacy, returns, shipping, payment, inspection, complaints, terms, general conditions; marketplace regulations, seller agreement, seller information), with the variables each needs, by key. Every text needs review by a legal professional. Follow pagination.next_cursor for more.
  • content.list (read-only): List posts and pages, drafts included, newest first. Filter by kind, language, status, parent page, text, category/tag or author. Follow pagination.next_cursor with the same filters for more.
  • content.list_banners (read-only): List banners of display placements (home hero, top strip…) within your reach, newest first, each with its version. Filter by placement key, unit, status or language.
  • content.list_blocks (read-only): List the block types this tenant can use in page layouts, with when to use each and its props JSON Schema. Only these blocks are accepted.
  • content.list_revisions (read-only): List the saved revisions of an entry, newest first (without their fields).
  • content.list_theme_variants (read-only): List the scheduled theme variants (seasons, holidays, hours) of a website.
  • content.list_types (read-only): List the tenant’s custom content types (team, projects, branches…).
  • content.order_placement (changes data): Set the order of the banners of a placement at once (first listed shown first).
  • content.publish (changes data): Publish the current draft of a post or page: readers see it at its address. Pass the version you read. With content.publish_own, only entries you created.
  • content.request_review (changes data): Ask a person to review and publish the draft of a post or page you wrote (emits content.review_requested). Use it when you may write but not publish. Pass the version you read.
  • content.resolve (read-only): Look up a public address in a language, as the website does: the published entry there, a redirect, or gone. Drafts are never returned.
  • content.restore_revision (changes data): Copy a revision back into the draft of its entry (the published version does not change until published again). Pass the entry’s version.
  • content.save_banner (changes data): Draft a banner, or change one (with id and version). Pictures must be public and fit the placement’s ratio and size; links point to an address or to an object such as catalog.product. A tool never turns a banner on: a person sets it active.
  • content.save_theme_variant (changes data): Create a theme variant as a draft, or replace one (pass id and version). It is never switched on by this tool: a person activates it.
  • content.save_type (changes data): Create a custom content type, or change one (pass key and version). Its own fields are custom fields of target content.type.<key>.
  • content.search (read-only): Search the posts and pages of one language (drafts included) by meaning and by words, best first, each with how it matched and the best passage. Good for finding related or duplicate content before writing.
  • content.seo_check (read-only): Check the SEO of the draft of a post or page without AI: missing or too long title and description for search engines, images without alt text, skipped heading levels, duplicate titles, missing translations. Changes nothing.
  • content.site_health (read-only): Get the last health check of a website: missing SEO descriptions or image alt texts, duplicate titles, broken links, hidden embedded records, finished countdowns and missing addresses asked for often, each with how to fix it. Checked every day; null before the first check.
  • content.suggest_seo (changes data): Ask the server’s AI model to suggest a title and description for search engines, a summary and up to 5 existing categories or tags for a draft. Saves nothing: apply what you accept with update. Uses AI tokens.
  • content.translate (changes data): Ask the server’s AI to translate a post or page into another configured language. Returns a request at once; a background job writes the translation’s draft (never published, marked ai_generated) without overwriting changes made meanwhile. Check it with get_translation_request. Uses AI tokens.
  • content.unpublish (destructive): Take a published post or page down; it goes back to draft and its address answers 404. Pass the version you read.
  • content.update (changes data): Change the draft of a post or page; omitted fields stay as they are. A published entry keeps showing its published version until published again. Pass the version you read.
  • content.update_page_layout (changes data): Change the draft block layout of a page: send the whole layout, or JSON Patch operations (at most 200, all or nothing). The result is checked like a person’s edit and stays a draft until published. Pass the version you read.
  • conversations.get_thread (read-only): Get a customer conversation in your scope with its latest 50 messages (oldest first).
  • conversations.list_callbacks (read-only): List call-back requests in your scope (phone numbers masked); calling back needs a person at the phone, so there is no tool for it.
  • conversations.list_calls (read-only): List the calls of a conversation in your scope, newest first (no phone numbers, no recordings). Follow pagination.next_cursor for more.
  • conversations.list_threads (read-only): List customer conversations in your scope, latest activity first; follow pagination.next_cursor for more.
  • conversations.reply (changes data): Send a message to the customer of a conversation in your scope; the same client_id never sends twice.
  • conversations.suggest_reply (changes data): Ask the AI for a draft answer to a conversation; it is stored for an agent to edit and send, never sent by itself.
  • customers.get_customer (read-only): Get one customer profile: totals, tier, custom fields. Phone and email are masked.
  • customers.list_groups (read-only): List customer groups (manual or rule-based) in your scope.
  • customers.preview_group (read-only): Count the customers a group matches now (rule groups: matching the rule; manual groups: members).
  • customers.reveal_contact (changes data): Show the full phone number and email of a customer. Every call is written to the audit log; give a reason.
  • customers.search_customers (read-only): Find customers in your scope by name, phone number or email, or list a group’s or tier’s customers. Phone and email are masked.
  • customers.upsert_group (changes data): Create a customer group (no id) or change one. A rule group’s members follow its rule shortly after; check with preview_group first.
  • files.confirm_upload (changes data): Complete an upload started with files.create_upload after sending the file: the server checks its size and SHA-256 and creates the file (a mismatching file is removed). Calling it again returns the same file.
  • files.create_upload (changes data): Start uploading a large file straight to storage (S3): give its name, type, exact size and SHA-256 (hex); you get a signed link. Send the file there yourself with the given method and headers, then call files.confirm_upload. On disk storage this answers files.direct_upload_unavailable: use files.upload_file instead.
  • files.delete_file (destructive): Delete a file and its content; it cannot be restored. Same access as get_file.
  • files.get_file (read-only): Get the details of a file (name, type, size, SHA-256). Your own files need files.upload; anyone’s need files.manage.
  • files.list_files (read-only): List the files you uploaded, newest first; follow pagination.next_cursor for more.
  • files.read_file (read-only): Get a file with its content as base64, for files up to 1 MiB; download larger ones with GET /api/v1/files/{id}/content. Same access as get_file.
  • files.upload_file (changes data): Upload a small file, its content base64-encoded (the size and type limits of the server apply). Upload large files with POST /api/v1/files.
  • forms.create (changes data): Create a form (open unless status is closed); websites show it from GET /api/v1/forms/public/{key}. Every problem is reported at once. Setting notify_emails also needs the permission forms.read (the mails carry the answers). fields is the whole list, in display order; each field is an object {key, type, label, help?, placeholder?, required?, options?, min_length?, max_length?, min?, max?}: key a lower-case letter then lower-case letters, digits or _; type one of text, email, phone, textarea, number, select, radio, checkbox, date, hidden, consent (at most one); label, help, placeholder are {"en": …, "vi": …}; options (only select, radio, checkbox) is a list of {value, label?}. success_message is {"en": …, "vi": …}.
  • forms.get (read-only): Get a form: its fields (keys, types, labels, options), status, settings, and its etag, needed to change it.
  • forms.get_submission (read-only): Get a submission: answers with labels, sender email, status, and its version, needed to change its status.
  • forms.list (read-only): List forms, newest first, with their fields and settings. Follow pagination.next_cursor for more.
  • forms.list_submissions (read-only): List the submissions of a form, newest first, with their answers and the labels of the form version they were sent with. Spam is left out unless status is spam. Follow pagination.next_cursor with the same filters for more.

  • forms.update (changes data): Change a form: only the given fields change. Close it with status: closed (there is no delete tool: deleting a form also deletes its submissions). Pass the etag you read. Changing notify_emails also needs the permission forms.read (the mails carry the answers). fields is the whole list, in display order; each field is an object {key, type, label, help?, placeholder?, required?, options?, min_length?, max_length?, min?, max?}: key a lower-case letter then lower-case letters, digits or _; type one of text, email, phone, textarea, number, select, radio, checkbox, date, hidden, consent (at most one); label, help, placeholder are {"en": …, "vi": …}; options (only select, radio, checkbox) is a list of {value, label?}. success_message is {"en": …, "vi": …}.
  • inventory.adjust_stock (changes data): Adjust stock in one warehouse; every line needs a reason code from the list inventory.adjustment. Sending the same reference and content again changes nothing.
  • inventory.create_receipt (changes data): Receive goods into a warehouse, against a purchase order or directly from a supplier; each line updates the average cost. The same reference and content again changes nothing.
  • inventory.create_transfer (changes data): Create a stock transfer between two warehouses as a draft (one line per variant); ship it with the REST endpoint POST /api/v1/inventory/transfers/{id}/ship.
  • inventory.get_levels (read-only): List stock levels (variant × warehouse) in your scope with on hand, available, reserved and average cost; follow pagination.next_cursor for more.
  • inventory.list_low_stock (read-only): List stock levels whose available stock is at or below their reorder point.
