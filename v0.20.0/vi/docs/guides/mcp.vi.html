Tài liệu Autoxide v0.20.0

Nối AI agent qua MCP

Tiếng Anh: mcp.md. Ví dụ dùng curl với biến API là địa chỉ máy chủ của bạn (export API=https://api.example.com), và SDK TypeScript (sdk/typescript). Chúng chạy như test với mỗi bản build, nên khớp máy chủ của phiên bản này.

AI agent gọi Autoxide như các tool qua Model Context Protocol ở /mcp (Streamable HTTP). Mỗi tool chạy cùng code với endpoint REST tương ứng, cùng permission: tool không bao giờ làm được điều REST với cùng permission không làm được.

1. Tạo key với ít permission nhất

Cho agent một API key riêng, chỉ với thứ công việc của nó cần. content.write_own cho nó viết bản nháp của chính nó; việc đăng vẫn do người làm.

curl -sS "$API/api/v1/auth/login" \
  --json '{"email":"admin@example.com","password":"correct horse battery staple"}'
# save: TOKEN=.data.access_token
# save: REFRESH=.data.refresh_token

curl -sS "$API/api/v1/auth/api-keys" -H "Authorization: Bearer $TOKEN" \
  --json '{"name":"Writing agent","permissions":["content.read","content.write_own"],"current_password":"correct horse battery staple"}'
# expect: 201
# save: AGENT_KEY=.data.key

curl -sS "$API/api/v1/auth/me" -H "Authorization: Bearer $AGENT_KEY"

2. Nối client

Khi máy chủ bật đăng nhập OAuth, client hỗ trợ nó (Claude, ChatGPT, Claude Code, IDE) kết nối chỉ bằng địa chỉ và người dùng duyệt nó trong giao diện của bạn: xem Kết nối client MCP bằng đăng nhập OAuth. Phần còn lại của mục này kết nối bằng API key, cách dùng được với mọi client.

Claude Code:

claude mcp add --transport http autoxide https://api.example.com/mcp --header "Authorization: Bearer $AUTOXIDE_AGENT_KEY"

Client MCP khác nhận một máy chủ Streamable HTTP kèm header, vd:

{
  "mcpServers": {
    "autoxide": {
      "type": "http",
      "url": "https://api.example.com/mcp",
      "headers": { "Authorization": "Bearer ${AUTOXIDE_AGENT_KEY}" }
    }
  }
}

Agent chỉ làm việc với một module thì nối thẳng tới endpoint riêng của module đó, /mcp/<module> (vd https://api.example.com/mcp/content): cùng xác thực và permission, nhưng chỉ có tool, resource và prompt của module đó, nên mô hình không phải đọc mô tả của mọi tool trên máy chủ. /llms.txt có link tới endpoint của từng module.

3. Agent làm được gì

tools/list chỉ hiện tool mà permission của key cho phép. Mô tả của mỗi tool kết thúc bằng permission cần có, và chú thích cho biết tool chỉ đọc hay phá huỷ (client hỏi người dùng trước khi gọi loại này). Tool deprecated ghi rõ trong mô tả và trong mọi kết quả (_meta.autoxide/deprecation), kèm tool dùng thay.

Giới hạn:

  • Request bằng API key dùng chung giới hạn của key (AUTOXIDE_HTTP_RATE_LIMIT_API_KEY_PER_MINUTE).
  • Mọi lệnh ghi vào audit log dưới tên key.
  • Kết quả AI là gợi ý và bản nháp để người duyệt; agent không tự đăng được gì.
  • Kết quả tool cùng hình dạng với REST: {"data": …}, hay một trang kèm pagination; lỗi mang cùng code.

4. Resource và prompt

Ngoài tool, /mcp có resource (tài liệu chỉ đọc: resources/list, resources/read) và prompt (mẫu lời nhắc cho việc hay làm: prompts/list, prompts/get). Cả hai theo permission như tool: resource chỉ hiện với người gọi có permission của nó, prompt chỉ hiện với người gọi được mọi tool mà prompt dẫn tới. Resource hay prompt người gọi không được dùng trả lời y hệt cái không tồn tại.

Ai đăng nhập cũng đọc được autoxide://kernel/llms.txt (cùng nội dung với /llms.txt) và autoxide://kernel/openapi.json (hợp đồng REST). Prompt không tự gọi gì: nó trả tin nhắn nói mô hình nên gọi tool nào, và đối số của người dùng nằm trong thẻ như <topic>…</topic>, được đánh dấu là dữ liệu.

5. Cho agent tự tìm đường: /llms.txt

/llms.txt là trang công khai theo định dạng llmstxt.org: tài liệu OpenAPI và /mcp ở đâu, xác thực thế nào, quy ước chung của mọi endpoint, các module đã cài và prompt, resource MCP. Trang sinh từ code lúc máy chủ khởi động nên luôn khớp phiên bản này. Link là tuyệt đối khi đặt AUTOXIDE_HTTP_PUBLIC_URL.

curl -sS "$API/llms.txt"

Dưới mỗi module, /llms.txt có link tới tài liệu OpenAPI và endpoint MCP riêng của nó và nêu tên các tool. Tài liệu OpenAPI của một module chỉ có các endpoint dưới /api/v1/<module> và các schema chúng dùng, cùng quy ước chung như tài liệu đầy đủ — đủ để gọi đúng module đó mà không phải nạp phần còn lại của API:

curl -sS "$API/api/v1/openapi/content.json"

6. Từ chạy nhanh tới một agent làm việc thật

Làm trọn trên máy của bạn, từ một thư mục trống tới một trợ lý trả lời được câu hỏi về tồn kho và doanh số. Bắt đầu từ mục Chạy nhanh (compose.quickstart.yml), nên máy chủ ở http://127.0.0.1:8080.

1. Đăng nhập và tạo key cho trợ lý. Dùng mật khẩu của quản trị viên trong file máy chủ đã ghi (docker compose -f compose.quickstart.yml exec autoxide autoxide initial-password). Chỉ cho key đúng thứ trợ lý cần — ở đây là đọc tồn kho, sản phẩm, giá, báo cáo và soạn hoá đơn nháp:

API=http://127.0.0.1:8080
TOKEN=$(curl -sS "$API/api/v1/auth/login" \
  --json '{"email":"admin@example.com","password":"<password from the log>"}' | jq -r .data.access_token)
curl -sS "$API/api/v1/auth/api-keys" -H "Authorization: Bearer $TOKEN" \
  --json '{"name":"Desk assistant","permissions":["inventory.read","catalog.products.read","catalog.prices.read","reporting.read","analytics.read","invoices.write"],"current_password":"<password from the log>"}' \
  | jq -r .data.key

Key (axk1_…) chỉ hiện một lần: cất vào trình quản lý mật khẩu. Xem key được làm gì bằng curl -sS "$API/api/v1/auth/me" -H "Authorization: Bearer axk1_…".

2. Nối client.

Claude Desktop nhận máy chủ cục bộ (stdio) trong file cấu hình (Settings → Developer → Edit Config, claude_desktop_config.json). Cầu nối mcp-remote (cần Node.js) nối nó tới máy chủ HTTP kèm header:

{
  "mcpServers": {
    "autoxide": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "http://127.0.0.1:8080/mcp", "--header", "Authorization:${AUTOXIDE_AUTH}"],
      "env": { "AUTOXIDE_AUTH": "Bearer axk1_…" }
    }
  }
}

Khởi động lại Claude Desktop; các tool hiện dưới biểu tượng công cụ của cuộc trò chuyện mới. (mcp-remote chỉ dùng HTTP thường với localhost; máy chủ ở nơi khác cần HTTPS.)

Cursor tự nói Streamable HTTP. Trong ~/.cursor/mcp.json (mọi dự án) hay .cursor/mcp.json (một dự án — đừng commit key):

{
  "mcpServers": {
    "autoxide": {
      "url": "http://127.0.0.1:8080/mcp",
      "headers": { "Authorization": "Bearer ${env:AUTOXIDE_AGENT_KEY}" }
    }
  }
}

Chạy Cursor với AUTOXIDE_AGENT_KEY=axk1_… trong môi trường, rồi xem Settings → MCP: autoxide phải liệt kê các tool. Muốn trợ lý hẹp hơn thì nối vào đúng một module, vd http://127.0.0.1:8080/mcp/inventory.

3. Giao việc thật. Bản cài mới chưa có sản phẩm hay tồn kho: thêm trước (qua trang xem API /api/docs sau khi đặt AUTOXIDE_HTTP_API_DOCS=true, hay giao diện của bạn). Rồi hỏi bằng lời thường; mô hình tự chọn tool, client hiện từng lần gọi trước hoặc sau khi chạy.

Điều giữ an toàn:

  • Key quyết định: tools/list chỉ hiện tool mà permission của key cho phép, và tool không bao giờ làm được hơn REST với cùng permission. Trợ lý ở trên đọc và soạn nháp được; không đổi tồn kho, không hoàn tiền, không phát hành hoá đơn được.
  • Đơn hàng đến từ checkout, không từ tool: không có tool nào đặt hàng thay khách. Agent soạn bản nháp (hoá đơn, nội dung, trả lời) để người xác nhận.
  • Lệnh ghi gọi lại an toàn (idempotency) và mọi lệnh ghi nằm trong audit log dưới tên key (/api/v1/audit).
  • Xong việc thì xoá key: DELETE /api/v1/auth/api-keys/{id}.
