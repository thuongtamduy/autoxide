- The Docker image is now distroless (Debian 13 `cc` base): no shell, `cat`, `rm`, `curl` or package manager, smaller to patch. It still runs as user `10001`, so existing volumes keep working. **Action needed:** anything that used `docker exec … sh`, `cat` or `curl` inside the container must use `docker debug` / `kubectl debug` or an `autoxide` command instead. The quickstart commands `exec autoxide cat data/initial-admin-password` and `exec autoxide rm data/initial-admin-password` are replaced by `exec autoxide autoxide initial-password` and `exec autoxide autoxide initial-password --remove`.
- New command `autoxide initial-password [--remove]`: prints (or deletes) the file where `autoxide serve` wrote the generated password of the first administrator (`AUTOXIDE_BOOTSTRAP_ADMIN_PASSWORD_OUT`). Exit 1 when the file does not exist, 2 for invalid configuration. It also works outside Docker.
- New command `autoxide healthcheck` (exit 0 when `/health/ready`, or `/health/live` with `--live`, answers 200): the image's `HEALTHCHECK` and the `app` service of `compose.yml` use it, so `docker compose ps` shows `healthy`. It reads only `AUTOXIDE_HTTP_ADDRESS`, so it needs no other setting; a server that never started (for example for a missing setting) simply does not answer and the container reports `unhealthy`.
